# Working on the Reading Atlas

This repository contains the public website at https://ditchthescroll.com/books/.

## Preserve the product

- Read README.md and WORK_LOG.md before changing the site.
- Preserve existing book IDs and the browser-storage keys. Users may have saved shelves and notes.
- Keep all public material free of private chat excerpts, credentials, personal contact information, family details, and local machine paths.
- Maintain bibliographic sources and distinguish editorial judgments from factual claims.
- Keep the site accessible, responsive, and usable without an account. Do not add analytics or remote storage without a product reason and authorization.
- Defense content belongs at the level of history, institutions, ethics, and legitimate engineering education. Longevity claims require evidence and uncertainty.

## Finish meaningful work

- Run `npm test` after a substantive change. For layout or interaction changes, verify the relevant flows in a real browser at desktop and mobile widths.
- Add a dated WORK_LOG.md entry describing what actually changed, what was checked, what was learned, and what remains uncertain. Use the user's actual local date; never fabricate past activity.
- Record AI assistance honestly. Do not claim the owner personally read every book or authored every implementation line.
- Make focused commits for real completed changes. If the user continues to authorize GitHub tracking, push those commits to the existing repository after validation. Do not generate empty commits or automatic streak activity.
- A commit is evidence of a project change, not proof of mastery. Learning entries should describe actual practice, experiments, mistakes, and results.
- Deploy only this atlas project when the user requests publishing. The root domain also hosts other applications; preserve its existing routes and content.

## Useful commands

- `npm run dev` — local server at http://127.0.0.1:4173/books/
- `npm test` — dependency-free checks
- `git status --short` — review intended changes

There is no automatic daily posting or unattended contribution generator. Future sessions should document actual work as it happens.
